# ジレンマ劇場 — ゲーム理論10本のオンライン実習

物語とイラストつきで10のゲームを遊び、選択と理由を Google スプレッドシートに集め、結果ページでクラス全体の傾向と AI による理由の分類を見るアプリです。

## ゲームとURL

すべての画面の上に、授業名（`js/config.js` の `COURSE_LABEL`：追手門学院大学 理工学部　コンピュータインタラクション 授業課題）を表示します。

| ID | ゲーム | 物語 |
|---|---|---|
| `pd` | 囚人のジレンマ（一回限り） | 怪盗ミケ、取調室にて |
| `bos` | 男女の争い（一回限り） | スマホの充電、0%（好きな場所はランダムに割り当て） |
| `stag` | 鹿狩りゲーム（一回限り） | 収穫祭前夜の森 |
| `chicken` | チキンゲーム（一回限り） | 一本橋のヤギ |
| `volunteer` | ボランティアのジレンマ（5人・一回限り） | シェアハウスの夜、ヤツが出た |
| `ultimatum` | 最後通牒ゲーム（一回限り、両方の役を決める） | 宝箱の山分け |
| `dictator` | 独裁者ゲーム（一回限り。1000円を見知らぬ相手と分ける。相手は断れない） | ふたり1組の福引き |
| `trust` | 信頼ゲーム（一回限り。預ける側と名人の両方の役を決める。預けた分は3倍） | 名人の畑 |
| `ipd` | 繰り返し囚人のジレンマ 2本セット（**おすすめ**：順番を学籍番号で自動に振り分け） | ラーメン激戦区 |
| `ipd_unknown` | 繰り返し囚人のジレンマ（回数を知らない：8〜12週） | ラーメン激戦区 |
| `ipd_known` | 繰り返し囚人のジレンマ（回数を知っている：10週） | ラーメン激戦区 |

- 遊ぶ：`https://<あなた>.github.io/<リポジトリ>/index.html?game=pd`
- 結果：`https://<あなた>.github.io/<リポジトリ>/results.html?game=pd`（`?game=all` で全体、繰り返しは `?game=ipd`）
- `index.html` だけを開くと、ゲームの一覧が出ます。

どのゲームも、最初に学籍番号とニックネームを入力し、選択のあとに理由（15文字以上）を書かないと送信できません。

## ナッシュ均衡の課題（quiz.html）

- URL：`https://<あなた>.github.io/<リポジトリ>/quiz.html`（ゲーム一覧の下にもカードがあります）
- 純粋戦略5問（マスをクリックして★をつける。均衡がないときは「ない」にチェック）、混合戦略3問（p＝Aが「上」の確率、q＝Bが「左」の確率を、分数か小数で入力。±0.006まで正解）。
- 正解は利得表から自動で計算しています（`js/quiz-data.js`）。利得表を書き換えれば答えも自動で変わります。
- 提出すると自動採点し、点数と解説（最適反応の○、均衡のマス、確率の求め方）を表示します。`config.js` の `QUIZ_SHOW_ANSWERS`（解説を見せるか）と `QUIZ_RETRY`（再挑戦できるか）で切り替えられます。
- 提出はシートの `responses` に `game = nashquiz` として記録されます（`choice`＝点数、`detail`＝各問の答えと正誤・何回目の提出か）。
- 結果ページの「ナッシュ課題」タブで、各自の1回目の提出による平均点・問題ごとの正答率・得点分布・よくある答えを表示します。先生モードでは学籍番号ごとの一覧（1回目と最新の点数、各問の○×）が出ます。
- 開閉は他のゲームと同じく、先生モードの「課題の開放」で行います（最初は閉じています）。

| 問 | 種類 | 正解 |
|---|---|---|
| 1 | 純粋 2×2 | （上, 左）※Aに支配戦略 |
| 2 | 純粋 2×2 | なし |
| 3 | 純粋 3×3 | （下, 右） |
| 4 | 純粋 3×3 | （上, 左）と（中, 中） |
| 5 | 純粋 3×3 | （下, 中）※Bに支配戦略 |
| 6 | 混合 | p＝1/3, q＝1/2 |
| 7 | 混合 | p＝3/4, q＝1/3 |
| 8 | 混合 | p＝1/2, q＝2/3, Aの期待利得＝4/3 |

## 課題の開放（先生が開けた課題だけ遊べる）

- 結果ページ（`results.html`）で先生モードに入ると「課題の開放」のスイッチが出ます。オンにした課題だけ学生が遊べます。繰り返しPDは2条件まとめて1つのスイッチです。
- **最初はすべて閉じています**（デモモードだけは、確認しやすいように最初から全部開いています）。授業の前に、使う課題をオンにしてください。
- 閉じている課題のURLを開くと鍵のかかった待ち画面になります。先生がオンにすると、**学生が何もしなくても**（ページを更新しなくても）数秒でその画面のまま入口に進みます。ゲーム一覧でも、閉じた課題には鍵マークが付いて押せず、先生が開くとその場で鍵が外れて「開きました！」とお知らせが出ます。閉じたときも同じように反映されます。
- 確認の間隔は `config.js` の `STATUS_POLL_SEC`（既定8秒）。確認するのは待ち画面とゲーム一覧だけで、ゲームのプレイ中や、画面を見ていない間（別タブ・スリープ中）は止まり、戻ってきたらすぐ確認します。ゲーム一覧で全部が開いた後は間隔を4倍に延ばします。Apps Script 側は状態をキャッシュから返すので、40人程度のクラスなら負担は小さく済みます。
- 開閉の状態はApps Script側（スクリプト プロパティ `OPEN_GAMES`）に保存され、**送信のときもサーバーで確認**します。プレイ中に閉じた場合は送信できず、選択と理由は画面に残るので、再開後に「もう一度送る」で送れます。
- 先生が閉じた課題を試したいときは、デモモード（`GAS_URL` を空にしたコピー）で確認するか、一時的に開いてください。

## 対戦相手の決まり方

| ゲーム | 先に参加した人がいるとき | いないとき（コンピュータの代役） |
|---|---|---|
| 囚人のジレンマ・鹿狩り・チキン | 自分以外の参加者から1人をランダムに選び、その人の手を使う | コイン投げ（50%ずつ） |
| 男女の争い | 反対の好み（フェス派⇔美術館派）の参加者から1人 | コイン投げ（50%ずつ） |
| ボランティア | 自分以外の参加者から最大4人 | 足りない人数分、各50%で名乗り出る |
| 最後通牒 | 反対の役の参加者から1人（提案額／乗るライン） | 0〜500Gを50G刻みでランダム |
| 独裁者 | 自分以外の参加者から1人（あなたが受け取る側のときの額） | 0〜500円を50円刻みでランダム |
| 信頼 | 反対の役の参加者から1人（預けた数／返す割合） | 預ける数0〜10個、返す割合0〜100%をランダム |
| 繰り返しPD | ― | 常にプログラム（しっぺ返し。`IPD_BOT` で変更可） |

- 候補になるのは、そのスプレッドシートにたまった**自分以外の参加者の最新の回答**です（同じ人が何度やっても1人として数える）。デモモードのサンプル回答は、本番では使われません。
- `js/config.js` の `OPP_MIN_POOL` で「何人たまるまで代役にするか」を変えられます（既定は1人＝誰か1人でもいれば人間の相手）。代役が相手のときは、結果画面にそう表示します。
- 相手の決め方が影響するのは**結果発表の画面だけ**です。シートに記録される選択・予想・理由と、結果ページの集計（全員をランダムに組んだ場合の分布など）には影響しません。
- 同じシートに複数クラスの回答がたまると、相手の候補も混ざります。クラスごとにシート（Apps Script）を分けてください。

## 仕組みのポイント

- **最後通牒ゲーム**は戦略法です。全員が「分ける側の提案額」と「受け取る側の最低受け入れ額」の両方を決め、理由も役ごとに書きます（シートでは2行）。
- **繰り返し囚人のジレンマの順番**：`?game=ipd` で始めると、学籍番号で半々に「回数を知らない→知っている」「知っている→知らない」を振り分けます（`IPD_ORDER` で全員同じ順にも変更可）。1本目のあとに「もう1本」のボタンが出て、ゲンさんの作戦は2本とも終わってから明かします。2本目かどうかはシートに記録され、結果ページの「初回プレイのみで比べる」で順序効果を除いた比較ができます。
- **繰り返し囚人のジレンマ**の相手（ゲンさん）はプログラムです。既定はしっぺ返し。`js/config.js` の `IPD_BOT` で、寛容なしっぺ返し（`gtft`）や、参加者ごとにランダム（`mix`、記録されます）に変えられます。理由は「1週目」「判断を変えた週」「最後のふりかえり」で書かせ、まとめて AI 分類にかけます。回数を知らない条件では、実際の週数（8〜12週）は伏せたまま終了通知で終わります。
- **予想**：2人ゲームは「相手はどうすると思うか」、ボランティアは「ほかの4人のうち何人が名乗り出ると思うか」も尋ねます。結果ページで予想×選択のクロス表を出すので、フォールス・コンセンサスや傍観者効果の話につなげられます。
- 同じ人が同じゲームを何度もやった場合、結果ページは既定で最新の回答だけを集計します（チェックを外すと全件）。

- **鹿狩りの利得**：鹿の価値は `STAG_VALUE`（既定6）。6のとき、利得の大きい鹿とリスクの小さいウサギがちょうど拮抗します（相手が鹿を待つ確率50%が分かれ目）。4にするとウサギがかなり有利になります（分かれ目75%）。
- **ゲーム理論の基準値**：結果ページに、ボランティアの混合戦略均衡（各人26%・誰も出ない22%、人数別の表）、鹿狩りの分かれ目、繰り返しPD（既知）でしっぺ返しの相手に対する最適（9週据え置き＋最終週値下げ＝320万円）を、クラスの実際の値と並べて表示します。

## AIによる理由の分類

先生モード（結果ページ上部、パスワード入力）で「AIで理由を分類」を押すと、未分類の理由を10件ずつ AI に送り、次の観点で判定します。

- **合理的**：利得・確率・相手の出方の予測、支配戦略、リスク比較、繰り返しでの仕返しの計算
- **感情的**：恐れ・不安・怒り・罪悪感・好き嫌いなど
- **規範的**：公平・信頼・約束・道徳など「こうあるべき」
- **認知バイアス**：フォールス・コンセンサス、傍観者効果、楽観バイアス、損失回避など（名前を1つ挙げる）
- **判定不能**

各理由について「中心となる観点（1つ）」と「含まれる観点（複数可）」をそれぞれ理由つきで返し、学生向けの一言も付けます。ゲームのルールと本人の選択・予想を一緒に渡しているので、「均衡から外れた」こと自体をバイアス扱いしないようにしてあります。「合理的」の基準は一般論ではなく、ルール説明に書いた相手の性質と最適解です。たとえば：
- 繰り返しPD（既知）：相手はしっぺ返しなので、「最終週だけ値下げ」「相手はまねするので協力を続ける」はどちらも合理的。「後ろ向き帰納法で初週から値下げ」も合理的な推論とするが、相手も合理的だという前提をおいている点をコメントで指摘する。
- 「自分が協力すれば相手も協力するはず」を魔術的思考とするのは一回限りのゲームだけ。繰り返しPDでは正しい推論。
- ボランティアの「誰かがやるだろう」は、確率やリスクを考えていれば合理的（均衡でも起きる）。「必ず誰かがやる」と根拠なく確信しているときだけ「責任の分散」としてバイアスにする。先生はカードごとに分類を修正でき、修正は「（先生）」として優先表示されます。観点の定義は `gas/Code.gs` の `SYSTEM_PROMPT` で変えられます。

## セットアップ（20分ほど）

### 1. スプレッドシートと Apps Script
1. 新しい Google スプレッドシートを作る。
2. 拡張機能 → Apps Script を開き、`gas/Code.gs` の中身を貼り付けて保存。
3. プロジェクトの設定 → スクリプト プロパティに次を追加：
   - `TEACHER_PASSWORD`：先生モードのパスワード
   - `OPENAI_API_KEY`：OpenAI の API キー（既定モデルは `gpt-4.1-mini`。`OPENAI_MODEL` で変更可）
   - Claude を使う場合は `AI_PROVIDER` = `anthropic` と `ANTHROPIC_API_KEY`（既定モデルは `claude-haiku-5-5`）
   - 任意：`PID_SALT`（学籍番号から匿名IDを作るときの文字列）
4. 関数 `setup` を一度実行して権限を承認（シート `responses` ができます）。`testClassify` を実行すると、API キーが動くかログで確認できます。
5. デプロイ → 新しいデプロイ → 種類「ウェブアプリ」、実行ユーザー「自分」、アクセス「全員」。発行された `…/exec` の URL を控える。
   - `Code.gs` を直したときは「デプロイを管理 → 編集 → 新バージョン」で更新してください（URL は変わりません）。

### 2. GitHub Pages
1. `js/config.js` の `GAS_URL` に、さきほどの URL を貼る。
2. このフォルダ一式（`gas/` は入れなくても可）を GitHub のリポジトリに置く。
3. リポジトリの Settings → Pages → Branch を `main` / `/ (root)` にして保存。

`GAS_URL` が空のままだと**デモモード**で動きます（回答はブラウザ内だけに保存、サンプル回答つき、先生モードのパスワードは `demo`、AI分類はキーワードによる簡易判定）。授業前の確認用です。

## プライバシー
- 結果ページ（誰でも見られる）にはニックネームと理由だけを出し、学籍番号は先生モードでのみ表示します。
- 学籍番号はシートに保存されます（加点用）。CSV は先生モードから出力できます。
